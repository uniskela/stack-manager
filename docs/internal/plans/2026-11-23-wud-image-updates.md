# Compose Image Updates Implementation Plan

Git remains authoritative for Compose configuration and update policy. Users can enter a candidate manually or accept a fresh WUD observation. Both sources use the same release review, source preview, and draft staging. Stage is available without WUD and without forge write access. Forge publication is a separate capability.

For the first migration, the source repository owns the policy. Read its `AGENTS.md`, `docs/wud-compatibility.md`, `docs/container-changelogs.json`, `docs/wud-update-groups.json`, and `docs/wud-update-approvals.json` at the same Git commit as the Compose files. Use its existing `scripts/tests/fixtures/wud-run-20261013/` case and newer compatibility tests as the parity reference. Inspect the files as data or test fixtures. The hosted application must never execute code read from a connected Git repository.

## 1. Read-only discovery

- [x] Add a WUD adapter under `src/server/providers/wud/`. Read the versioned WUD 9.9 container contract with `GET /api/containers` and a read-scoped Bearer token. Reuse the outbound address policy, pin the validated address for TLS, decline redirects, and cap response size and request time. Persist only the fields needed for source matching and review. Test with fixture responses, connection failures, and prohibited destinations.
- [x] Add a connection per workspace and an explicit watcher and Compose project mapping per stack. Store the token through `CredentialService` and persist a sanitized last-successful snapshot, timestamp, and last failure. Use durable jobs for background and operator refresh. Changing the connection discards its old snapshot. An in-flight refresh may only save results for the connection revision it read.
- [x] Use `SourceService.readFile()` to inventory the primary committed Compose file. Match by watcher, Compose project, service, canonical image and installed reference. Expose a stack view and a workspace queue with availability, drift, stale, excluded, unsupported, and unmatched states. Fixtures must cover two projects running the same image, stale registry observations, conflicting replicas, source `wud.watch=false`, and image tags containing interpolation. Verify with `pnpm check` and `pnpm build`.

## 2. Changelog review and bulk drafts

- [x] Add manual and WUD candidates to one planner on stack and workspace views. Accept a public changelog URL override and read `.stack-manager/image-updates.json` for persistent per-image and per-service links, source switches, exclusions, and review behavior.
- [x] Generate one reviewed draft per Compose file with exact, format-preserving tag edits. Verify the fetched commit and new content at staging, preserve concurrent drafts, and recheck any WUD recommendation. Stage independent files separately.
- [x] Show links from an existing `docs/container-changelogs.json` for repositories with an external WUD group policy. Keep those repositories on their existing staging workflow until Stack Manager supports their linked files, TechStack and compatibility checks.
- [ ] Use the existing changelog catalog and its schema, including image aliases, exact upstream mappings, tag templates, and per-source patterns. Add per-image links and service overrides for workspaces without a committed catalog. Treat submitted URLs and WUD-provided links as evidence sources and fetch them through bounded HTTPS with a separate public-destination policy and explicit allowances for private hosts.
- [ ] Preserve the repository-specific exclusions documented in `AGENTS.md` and implemented in `scripts/wud-updates.sh`. WUD supplies watcher and tag-filter results. Use its Compose config path to suggest a stack mapping when there is exactly one tracked match. Treat it as an untrusted hint and validate any translation against tracked paths. Keep non-repository and unresolved services visible as manual work.
- [ ] Capture the exact Git-pinned comparison and upstream release evidence expected by `scripts/wud-changelog-check.py`. Keep `ok`, `review`, `block` and `skip` as evidence decisions. Apply the contextual policy separately so keyword matches can become advisories, real incompatibilities stay withheld, and incomplete critical evidence stays a draft. Drive this per candidate or atomic group, never from the aggregate gate exit code.
- [ ] Preview changes against the committed blob. Commit the selected image scalars, configured dependent files and required TechStack entries together as defined by the repository's group policy. Store candidate identities, source commit/blob and evidence with the preview. Stage with a conditional write that preserves existing drafts and rejects changed blobs or candidates. Test comments, quoting, concurrent drafts, overlapping edits, and preserved `env_file` references. Keep unresolved digest-only updates informational.

## 3. Gitea PR publication and cutover

- [ ] Add a capability-gated branch/PR workflow to the Git provider. Use an isolated index and push without force. For the first migration, keep one routine PR per repository, independent review PRs per atomic group, and drafts for evidence gaps. Preserve confirmed incompatibilities and unsafe linked-image combinations as withheld outcomes. Reuse repository locking and source validation.
- [ ] Detect overlaps against open PRs. Follow the source repository's WUD-first policy for ordinary project PRs by recording overlaps and relying on its image guard and reconciliation process. Keep existing automation PR identity and update trailers compatible with those checks. Reconcile by head branch and commit after uncertain publication. Preserve human changes on existing branches and verify that branch pushes leave tracked-branch deployment routing untouched.
- [ ] Compare both workflows in report-only mode, including the installed WUD API shape and credential mechanism. Keep the existing CI image guard and reconciliation active through cutover. Document setup, matching, status meanings and rollback. Add an authenticated WUD HTTP trigger as an optional refresh signal after polling works independently.
